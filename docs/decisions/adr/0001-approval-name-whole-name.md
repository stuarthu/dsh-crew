# ADR 0001：审批文件名按「整个文件名」匹配，用自己写的边界字符类

## 背景
guard 原来只要命令文本里**含有**审批文件的名字就拒绝，而这条检查故意排在「信任 root
会话」之前。于是一个名字里刚好带着这段文字的作业分支（比如 `crew/push-ok-flow`），它的
每一条 git 命令都被拒，连用户自己的会话也一样，报错还说「你碰了审批文件」。新的第 17 步
几乎每条命令都由作业 slug 拼出来，所以这个假警报会让整步在这种分支上没法用。修的时候
必须选：拿什么当「名字的边界」。

## 选项
- **A** 用 JavaScript 的 `\b`。最短，但 `\b` 把 `-` 当成边界，所以 `\bpush-ok\b` 仍然能
  在 `push-ok-flow` 里匹配上——正是要修的那个假警报。
- **B** 自己写一个边界字符类：两边只要还是「能构成更长文件名的字符」，就认为命令说的是
  另一个文件。代价是多一个字符类，而且里面的 `-` 必须转义。
- **C** 不用正则，改用已有的 `tokensOf()` 按空白切词。看着更朴素，但重定向和文件名是
  同一个 token，`>push-ok` 会漏过去。

## 决定
选 **B**：`[^A-Za-z0-9._+\-]` 当两边的边界，`/push-ok` 和 `>push-ok` 算命中，
`push-ok-flow` 和 `push-okay` 不算。同一个决定里还定了三件跟着走的事：配置来的名字先
转义（它是用户可配的，不能当模式读）；完整路径走同一条规则，所以审批文件旁边的 `.bak`
不再被拒；字符类里的 `-` 靠转义而不是靠它排在末尾的位置，而且模式在 mount 时只建一次
——写坏了在启动时炸，不在之后每一条 shell 命令上炸。文件夹形状的 `approvalFile` 同样
改成 mount 时抛错，它原来会让 `basename()` 返回上一级目录名。

## 谁要求的
没有人。这是干活时撞上的选择，所以按「有人要求过吗」的判据，它是 ADR 而不是 CRD。
（要不要修这个 bug 是用户提的，记在 CRD 0001；这里定的是「怎么修」，没有人要求过。）

## 出处
`7c1fbe9`（`git log` 里那条提交信息记的就是这件事），代码在 `host/git-guard.js` 的
`approvalNamePattern()`。
