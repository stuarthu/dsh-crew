## 这份 CRD 为什么迟到了，以及迟到本身是个什么错

`CRD 0023` 决定一（用户 2026-08-21 定的形状）写的是**只追加不覆盖**，四件事：

> 确认过的原话永不删除，**PM 写一份 CRD**，把修正标注日期后写在原话**旁边**，继续干活，
> 并在文档里用一个**固定标题**把每一条都列出来。

PRD 的 B12 行也写着「PM 写一份 CRD」。**本作业做到了四件里的三件**：原话一条没删、
修正都标了日期写在文末的固定标题下、一次都没停工。**漏掉的是「写一份 CRD」这一件。**

**而漏掉它有一个原因，那个原因本身就是本作业在修的那种缺陷**：同一条规则的四个落地处，
说的不是同一件事。文档评审逐字并排读出来的：

| 落点 | 要不要 CRD |
| --- | --- |
| `CRD 0023` 决定一 | **要** |
| PRD 的 B12 行 | **要** |
| `roles/pm.md` 的「你能写什么」那一节（四条 bullet） | **不提** |
| `roles/pm.md` 的 `## Hard rules` | **要** |
| `principles.md` 规则 B 的 PM 那一半 | **不提** |

**PM 照着较松的那一份做了。** 而 PRD 第 5–7 行因此有一句假话：

> 每次改动记在 `docs/decisions/crd/` 里那份 CRD 的 **Applied** 行，以及 git history 里。

那句话在写下的时候就是假的（当时那份 CRD 不存在），一直假到今天。
**这是 `gaps.md` 第 35 条那个形状**：一句散文可以在写下的那一刻就已经不对了，
而没有任何检查会发现。

## 什么要改

**不是范围，不是任何一条要做的事。** 这份 CRD 补上一件本来就该有的记录，
并让 PRD 第 5–7 行那句话变成真的。

**另外要改四份文件里那两处不提 CRD 的地方**，让四个落点说同一件事——
那是 **T-91** 的活（产品文件，engineer 改），不是这份 CRD 的活。
**选的是「保留要 CRD 的那一版」**，理由：PRD 删掉版本历史的全部理由就是
「CRD 的 Applied 行已经有了」。反过来（删掉 CRD 那一半）要同时改 `CRD 0023`
——那是一份历史快照，按 `ADR 0017` 不该改——所以那条路更贵。
