# ADR 0015：里程碑那些带 `grep` 命令的检查，该写在哪一份文档里

- **状态**：已采纳（推荐），2026-08-21
- **决定人**：crew architect。**没有人要求过这件事**——它是 `docs/research/document-types.md`
  这份 websearch 回来之后自己冒出来的一个「怎么做」的选择，所以它是 ADR，不是 CRD。
  `docs/decisions/crd/0023-req-interview-six-decisions.md` 决定六的末尾把它点名交给 architect。
- **落在哪里**：写进 `principles.md` 和 `roles/pm.md` 的**规则**（A6）。
  **本作业自己那份 PRD 不改**——它是判本作业的标准，只有 PM 能改它，而且这个决定管的是
  下一件作业怎么写，不是回头修这一件。

## 在决定什么

一份 PRD 的每个里程碑今天带一节 **DoD**，里面每一条都写着「怎么算做完」加**一条确切的
`grep` 或 `node` 命令**。本作业的 PRD 有 16 条这样的检查。

**问题**：两份都很实在的依据，说的是相反的话。

- **外部来源说：不该在 PRD 里。** Cagan 的 PRD 模板（`© 2005 SVPG`，2026-08-21 读）
  只要求一份 PRD 写下 **Release Criteria**——六条非功能的门槛，不是逐条的验法。
  Atlassian 的模板、Figma 的清单也都不含逐条验法；Figma 的原话是
  「focusing on **what** you're building rather than **how**」。
  逐条的验法在 `ISO/IEC/IEEE 29119-3:2013` 里属于 **Test Case Specification**
  （identifier / objective / preconditions / inputs / expected results），
  在 Cagan 那里属于「QA 能照它写出测试计划和用例吗」——**照它写出来的东西，不是它本身**。
- **本仓库说：必须在它管的那份文档里。** `docs/decisions/crd/0010-dod-is-a-section.md`
  的理由是一次真的事故：上一件作业把 75 条编号的验收检查放在一份单独的 DoD 文件里，
  那个文件按搬运步骤被丢掉，**75 条一起丢**，48 条靠 QA 用例的头部注释救回来。
  所以 `DoD` 从此是**一个章节**，长在它管的那份文档里，永远不是一个文件。

两边都对，而且它们不是在争同一件事：外部来源在说「PRD 是给谁读的」，
本仓库在说「一条检查离它管的工作有多远就有多容易丢」。

## 桌上的每一个选项

### 选项 A：照旧——16 条连命令一起留在 PRD 里

- **是什么**：今天的样子。每个里程碑一节 DoD，每条一句「怎么算做完」加一条确切的命令。
- **代价**：PRD 变长，而**用户自己抱怨过的就是「太长」**（`~/req` 第 6 项原话
  `too long`）。一个只想知道「这件活要干什么」的读者，要翻过 16 条 `grep` 才看到风险表。
- **以后会在哪里疼**：PRD 是给用户看的、用来点头的文档。里面装着只有写代码的人看得懂的
  命令，用户点头时就没有真的读过那一半——那等于让他给一份他没读的标准盖章。
- **为什么它输了**：它把用户抱怨的那件事（太长）当成不存在。

### 选项 B（**推荐**）：PRD 每条只说「什么算做完」，命令下沉到任务行

- **是什么**：一条 DoD 拆成两半，两半都留在仓库里。
  - **PRD 里**：一句用户读得懂的话——「`roles/pm.md` 的第 2 步是苏格拉底式访谈」。
  - **任务行的 DoD 章节里**：那条确切的命令——「压平文本之后
    `Stop when the answers are settled` 出现 0 次」。
  一条 DoD 因此永远指得出它的两半在哪：PRD 说**什么**，任务行说**怎么查**。
- **代价**：同一件事写在两个地方，两边可能对不上，而且对不上的时候没有任何东西会红。
- **为什么它没输**：因为两半**说的不是同一句话**。PRD 那半是给用户的判据，
  任务行那半是给机器的命令。它们不是一份东西的两份拷贝，所以不存在「拷贝走样」这种失效。
  真正会走样的是「同一句话抄两遍」，那是选项 D。
- **它接住 `CRD 0010` 的理由吗**：接住了。`CRD 0010` 怕的是**检查离工作太远、
  而且住在一个会被丢掉的文件里**。这里两半都在仓库里、都在 git 里，
  而命令那一半离工作**更近**了——它就在写那件活的任务行里。

### 选项 C：16 条整个移进 `docs/design/tasks.md`，PRD 里只留一句「里程碑做完的意思」

- **是什么**：里程碑的 DoD 不再存在，只有任务行的 DoD。
- **代价**：用户失去他点头的那张清单。他要知道 M1 做完是什么意思，就得读 19 个任务行。
- **以后会在哪里疼**：里程碑是**用户判的**（`principles.md` 5）。判据搬到用户不读的文件里，
  就等于取消了那道门。而且 `CRD 0010` 明说 DoD 长在**它管的那份文档**里——
  里程碑是在 PRD 里定义的。
- **为什么它输了**：它省的是用户的阅读量，代价是用户的那一票。

### 选项 D：两处都写全，PRD 和任务行各一份完整的 16 条

- **是什么**：抄一遍。
- **代价**：同一句话两份拷贝，改一处忘一处。
- **以后会在哪里疼**：这个仓库刚刚为这件事付过一次代价——同一个数字（受影响的提交数）
  在一个文件里写成两个值，是 T-47 数出来才发现的。
- **为什么它输了**：两份拷贝就是两份，早晚不一样，而且不一样的时候看不见。

### 选项 E：单独一份测试计划文档，16 条搬进去

- **是什么**：`ISO/IEC/IEEE 29119-3` 的形状——一份 Test Plan、一份 Test Case Specification。
- **代价**：多一份文档，多一个要保持同步的地方。
- **以后会在哪里疼**：如果它是单次用的（放作业文件夹），**它就是那 75 条检查丢掉的那条路，
  一模一样**。如果它是长期的（放 `docs/`），那这个仓库就有了第三个装检查的地方，
  而没有任何规则说哪一条该去哪一个。
- **为什么它输了**：它要么重演一次已经发生过的事故，要么造出一个没人维护的第三个家。

## 推荐

**选项 B。** 一条 DoD 的两半各归各位：**PRD 说什么，任务行说怎么查**——
用户读得懂他要点头的东西，命令住在它管的那件活旁边，两半都在仓库里，谁也丢不掉。

## 它不证明什么

- 它**不**保证 PRD 会真的变短。PRD 变长的另一个原因是 `CRD 0023` 决定一
  （确认过的原话永不删除，只追加）。那是用户自己选的交换，这个 ADR 不动它。
- 它**不**是对本作业那份 PRD 的批评，也不要求改它。本作业的 PRD 是按今天的规则写的，
  按今天的规则它是对的。
