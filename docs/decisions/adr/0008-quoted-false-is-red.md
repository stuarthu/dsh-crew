# ADR 0008：`continue-on-error` 只认三种写法算 `false`，别的都判红

- **状态**：已采纳，2026-08-21
- **决定人**：T-46（工程师），PM 复核。**没有人要求过这件事**——团队在修一个失效的钉子时
  撞上了它，所以按 `CLAUDE.md` 和 `principles.md` 19 的规矩，它是 ADR，不是 CRD。
- **落在哪里**：`tools/verify-mount.mjs`，`continue-on-error` 那一段的注释和
  `mayFailAt` 那一行。断言在 `docs/qa/T-42/case-08-publish-test-gates-publish.mjs`。

## 事情从一个从来没生效过的豁免开始

`publish.yml` 里那一步 `npm test` 必须**不许失败**，否则测试就没在把发布拦住。原来的钉子是：

```js
/^[ \t]*continue-on-error:[ \t]*(?!false\b)/m
```

意思本该是「有 `continue-on-error:`，而且值不是 `false`」。它不成立：**一个否定前瞻放在变长
匹配后面，是不受锚定的**。`[ \t]*` 会回溯到零宽，于是 `(?!false\b)` 在 `false` **前面那个空格**
的位置被测试，空格不是 `false`，所以整个模式每次都匹配。

后果是两头都坏：那个 `false` 豁免**从来没豁免过任何东西**，而 `continue-on-error: false`
——显式写出默认值，很多团队的规范要求这么写——在一份**完全正确**的文件上被报成红，而且
错误信息说的是事实的反面。**一道会在正确文件上变红的门，教人不再看它。**

这个教训和这个仓库之前那批不是同一条。之前那批是「用 `[ \t]` 不要用 `\s`」——而这一行用的
正是 `[ \t]`。新教训是：**变长匹配后面的前瞻不受锚定；要判断一个值，就把值取出来单独判断。**

## 决定：接受集是 `false`、`False`、`FALSE`，别的一律红

修法不再用前瞻，改成把值捕获出来：

```js
const continueOnError = [...testStepBlock.matchAll(/^[ \t]*continue-on-error:[ \t]*([^\n]*)$/gm)]
  .map((match) => match[1].replace(/[ \t]+#.*$/, "").trimEnd());
const mayFailAt = continueOnError.findIndex((value) => !/^(?:false|False|FALSE)$/.test(value));
```

`findIndex` 不是 `find`：**空值本身就是一个红答案**，而 `find` 会返回假值 `""`，然后被读成
「一切正常」——那又会变成一个不可能失败的钉子。

那三种写法是 YAML 1.2 核心 schema 读成布尔 `false` 的全部拼法。T-46 把每一种写法都拿真的
YAML 解析器验过才决定，不是凭记忆：

| 写法 | YAML 读成 | 钉子的答案 | 理由 |
| --- | --- | --- | --- |
| `false` / `False` / `FALSE` | 布尔 false | **绿** | 就是这次要修的东西。判红任何一种都是把原来的缺陷再犯一次 |
| 多个空格、制表符、行尾空格、行尾 `# 注释` | 布尔 false | **绿** | 空白和注释是 YAML 的事，不是钉子的事 |
| `"false"` / `'false'` | **字符串** `"false"` | **红** | YAML 给的不是布尔。钉子不去猜某个 runner 怎么强制转换 |
| `fAlse` | 字符串 | **红** | 也是字符串。一个真值字符串在这里意味着那一步**真的可能失败**——危险方向 |
| 值换到下一行 | 布尔 false（合法） | **红** | 一行读不出下面那行是 `false` 还是 `true`，所以**大声拒绝**，不放行 |
| 表达式 | 字符串 | **红** | 表达式可以求值成 true |
| `0`、`no`、空值 | 各不相同 | **红** | runner 可能转也可能不转，钉子不猜，也没有任何规范要求这么写 |
| `continue-on-error:false`（无空格） | **解析错误** | 绿，而且不要紧 | 那根本不是 YAML 映射，GitHub 会拒绝解析整个文件，什么都发不出去 |

## 为什么「有分歧就往红那边错」赢了

这个钉子守的是**这个仓库唯一不可撤销的动作**:`v*` tag 触发 `npm publish`，发出去的版本收不回。
所以两种错的代价不对称：

- **误红**的代价是一个人被拦一次，看一眼错误信息就明白了——而错误信息会**列出它接受哪三种
  写法**，所以这个人五秒钟就能自己解决。
- **误绿**的代价是发布了一个测试根本没在拦的版本，而且没有任何人会知道。

所以凡是 YAML 的答案和钉子的答案**可能**不一致的写法，一律判红，并且把接受集写进错误信息。
这条不是「宁严勿宽」的口号——它是因为这两种错的代价差了几个数量级。

## 为什么大小写不做成不敏感

看起来 `/^false$/i` 更友好。不做，因为 `fAlse` 在 YAML 里是**字符串**而不是布尔，而一个非空
字符串在某些 runner 里是真值——也就是那一步**真的可能失败**。做成大小写不敏感，等于把一个
危险写法放行成安全写法。接受集就是那三种拼法，不多不少。

## 这个决定自己怎么被守住

`docs/qa/T-42/case-08` 钉住了两头:三种拼法保持**绿**，`"false"`（带引号）保持**红**。

钉住带引号那一条的目的不是钉行为,是**钉决定**:防止以后有人"好心"把接受集放宽到「任意
大小写、带不带引号都行」。没有那条断言,这份 ADR 只是一段散文。

## 它证明不了什么

钉子读的是**一行文本**。一个作业层面的 `if:` 跳过整个 job、一个 `run: |` 块里第二行写
`exit 0`、或者一个不是 bash 的 shell，都在它之外。这些记在 `docs/qa/gaps.md` 里，不在这里
装作已经盖住了。
