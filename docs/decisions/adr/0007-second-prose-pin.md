# ADR 0007：第二个散文钉字符串——`the tree was moving`

## 背景
`roles/engineer.md` 和 `roles/qa.md` 都写着一条规则：跑套件时如果红在别的活着的任务正在写的
文件上，那不是关于自己工作的证据，要说「the tree was moving」并点名那个文件。这条规则丢掉
是**看不见的**：没有检查、没有报错，crew 只是开始把别人半保存的文件当成缺陷来报。

而这条规则里没有任何命令、路径或字段名，只有那一句话本身。

## 选项
- **A** 不钉。代价：规则可以被静默删掉，而这次作业已经用两次假红证明过它值钱。
- **B** 钉住 `the tree was moving` 这个短语。代价：这是**散文**，任何一次合法的改写都会让检查
  变红，即使规则还在。

## 决定
选 **B**，并且照 `ADR 0004` 的先例处理它的脆性：失败信息必须明说「合法的改写意味着**在同一个
提交里**改提示词和改这个字符串」。两个文件里那句话都被刻意放在单独一行，就是为了能被 grep。

`ADR 0004`（并行规则的锚点）是同一个取舍的第一次；这是第二次。两次的判断一致：一条丢了看不见
的规则，值得一个会因为改措辞而红的钉——因为「改措辞时顺手更新检查」是可以要求的，「记得一条
没人守的规则」不是。

## 谁要求的
没有人。`T-27` 的工程师在装钉子的时候撞上这个选择，并且它自己说了：「这是同一个取舍的第二个
字符串，按判据它该有一份 ADR 或者往 0004 里加一行，但我不拥有 `docs/decisions/adr/`。」
所以它报上来，由 PM 写。

**选项一节的来源，说清楚**：它没有写 `Q-` 文件——它没有被卡住，是在自己的范围内做了决定然后
汇报。所以这里引用的是它的**汇报原文**，不是 `Q-` 文件。CRD 0006 的规则只写了「引用 `Q-`
文件」，漏了这种情况，已在 CRD 0006 修订三里补上。
