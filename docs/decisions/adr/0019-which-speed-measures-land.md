# ADR 0019：A1f 到底把哪几条提速办法写进 `roles/pm.md`

- **状态**：已采纳（推荐），2026-08-21
- **决定人**：crew architect。PRD 的「还没定的问题」第 1 条**把这件事明确交给本作业的 ADR**：
  「本文件列了四条……哪几条真的进 `roles/pm.md`，由本作业的 ADR 定，PM 决定。」
  所以最终拍板的是 PM；这份 ADR 摆选项、给推荐。
- **落在哪里**：T-65 的任务行（`roles/pm.md` 第 10、15 步）。

## 在决定什么

A1a 到 A1e 是用户直接要的五条提速办法。**A1f 是「你自己再想几条」**。
PRD 里已经列了四条候选。要决定的是哪几条真的写进产品文件。

**判据只有一条**：它省下的是**真实的往返轮次**吗？
省不下往返的东西不是提速办法，写进去只会让一份 1485 行的文件更长
（PRD 的发布标准给了这个文件 1900 行的硬上限）。

## 桌上的每一个选项

### 候选一（**进**）：文档评审按文档并行，一个 agent 一份文档

- **是什么**：今天一个 `crew_doc_reviewer` 读一批文档。改成一份文档一个 agent，
  全部并行，PM 收全部报告。
- **它省下什么**：和 A1c 那一轮 QA 完全同一个形状（一个 agent 一条用例）。
  上一件作业最后一轮文档评审一个 agent 读了十几份文件，回来 8 条 blocking——
  一份一个 agent，这一轮的墙上时间从「串着读十几份」变成「最慢那一份」。
- **代价**：agent 数量变多。这个仓库的 PM 有并发上限，超了要问用户。
- **以后会在哪里疼**：一份文档一个 agent，就没有任何一个 agent 看得见**跨文档的矛盾**——
  而跨文档矛盾正是 Part B 那 12 条的本质。所以这一条必须配一句话：
  **PM 自己负责跨文档那一层**，或者最后留一个只看交叉引用的评审。
  这一点要写进 `roles/pm.md`，不能只写「并行」两个字。
- **为什么它进**：它是四条里唯一一条和用户已经点头的形状（A1c）完全一致的，
  而且省下的是最慢那一轮的墙上时间。

### 候选二（**不进**）：交工前一次关门扫描

- **是什么**：PM 在最后提交之前，把本作业改过的每一个字符串再扫一遍。
- **它省下什么**：**什么都不省。它是一道质量门，不是提速办法。**
- **代价**：多一轮 PM 自己的工作。
- **为什么它输了**：两个理由。
  ① A1f 问的是「别的**提速**办法」，而这一条花时间不省时间；
  ② 第 18 步已经在做同一件事（「Re-read every DoD section this job touched」）。
  再加一段没有判据的「再读一遍」，最可能的结局是一句谁都不做的话——
  这个仓库已经有过一段这样的话（第 11 步的「if a file changed that no task owns, stop」，
  而手册自己叫 PM 写的文档从来不属于任何任务，那就是 B1）。

### 候选三（**进**，四条里证据最硬的一条）：DoD 里的验证命令，PM 先自己跑通

- **是什么**：PM 写完一条 DoD 之后，**自己跑一遍那条命令**，确认它今天真的会红
  （即：在改动之前它是失败的）。跑不出红的命令不许写进 DoD。
- **它省下什么**：一条**永远不会红**的命令，会让一个 engineer 或一个 QA 白跑一整轮——
  他照着它做，它绿了，大家以为做完了，而它从写下的那一刻起就绿。
- **本作业自己的证据（三处，全在本作业的 PRD 里）**：
  - **DoD 第 3 条**要求 `Stop when the answers are settled` 这句话消失。
    这句话在 `roles/pm.md` 里真的存在，但它**在第 236–237 行换行了**
    （`Stop when the answers are` / `settled.`），所以按字面 grep 一次都命中不了。
    **这条检查从写下的那一刻起就不可能变红。**
  - **DoD 第 6 条**用 `grep -c 'quick' roles/pm.md`。`grep -c` 给的是一个数不是位置，
    而这个文件里第 36 行的 `a quick look` 是正常英文，改完之后还在，所以那个数永远不是 0。
  - **DoD 第 15 条**说「`node tools/verify-mount.mjs` 里两份 README 的对齐检查」。
    `tools/verify-mount.mjs` 里**一次都没有提到 README**（实测 0 处）。那道检查在 `docs/qa/T-59/`。
- **这不是新发现，是第八次**：`docs/qa/T-60/case-09` 的头部注释写着
  「A verification that cannot fail is not a verification. It is the seventh time
  the same trap bit this job.」它还给了办法：**数两次**——压平文本数一次、逐行数一次，
  两个数不一样就说明那句话换行了。
- **代价**：PM 写 DoD 的时候慢一点。
- **为什么它进**：四条里唯一一条**在本作业自己身上抓到三个实例**的。

### 候选四（**进**）：QA 开跑前冻结 DoD

- **是什么**：那一轮 QA 启动之前，DoD 不再改。要改就等这一轮回来。
- **它省下什么**：`CRD 0020` 记着上一件作业三个评审最多跑到 3 轮，
  其中**有 3 轮是「评审跑完代码又变了、评审因此过期」**。DoD 在 QA 跑的时候变，
  是同一件事早一步发生：QA 按旧的 DoD 写完清单，清单当场作废。
- **代价**：一处 DoD 的错误要多等一轮才修。而 `CRD 0023` 决定一（只追加，不覆盖）
  正好给了这件事一个不用停工的做法：**修正写在原话旁边，标日期，继续跑。**
  所以这一条和「只追加」是配着用的，不是互相打架。
- **为什么它进**：它省下的是**已经被测量过**的浪费（3 轮过期评审）。

## 推荐

**进三条：候选一、候选三、候选四。候选二不进。**

一句话：**三条都省下已经被测量过的往返，候选二花时间不省时间，而且第 18 步已经在做它。**

## 它不证明什么

- 这三条**没有任何一条能被 `npm test` 检查**。它们是 PM 的行为，写在散文里，
  由文档评审读。这不是漏了，是测不到——该进 `docs/qa/gaps.md`。
- 候选一的那个洞（一份一个 agent 就没人看跨文档矛盾）**这份 ADR 没有关掉它**，
  只要求 T-65 在散文里写清楚谁负责那一层。真正关掉它要另一件活。
