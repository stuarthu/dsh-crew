# ADR 0009：两份新 persona 各自写全，不共享、不互相指路

- **状态**：已采纳（推荐），2026-08-21
- **决定人**：architect（`paired-engineers` 作业，拆任务时撞上）。**没有人要求过这件事**——
  用户要的是「两个 engineer」，两份 persona 长什么形状是干活时撞上的选择，所以按
  `principles.md:589` 和 `CLAUDE.md` 的规矩，它是 ADR，不是 CRD。
- **落在哪里**：`roles/test-engineer.md`（T-53）、`roles/code-engineer.md`（T-54）、
  `roles/engineer.md`（T-55）。

## 选择是什么

`roles/engineer.md` 今天 241 行，里面很大一块是**三个 engineer 共同**要遵守的东西：
读哪些文档、只碰自己拥有的文件、库可以选不可以加、代码和注释用英文、不碰 git、
「假红不是证据」、报告要什么。

两个新角色需要其中大部分，加上各自独有的规则。所以问题是：**这些共同的话，写几遍？**

## 看过的三个选项

| 选项 | 好处 | 代价 / 为什么输 |
| --- | --- | --- |
| **A（推荐）三份文件各自写全**，共同的话在三份里各写一遍，措辞可以不同 | 每个子 agent 拿到的提示词是完整的、自足的，一份文件读完就能干活。dsh 的模型本来就是「一个角色一份 persona」（`host/roles-preset.js:47` 对每个角色调一次 `readRoleText`），这个选项和平台形状一致 | **一样的规则有三份拷贝，会各自漂移。** 改一条共同规则要改三个文件，而且没有任何检查会提醒你漏了第三个 |
| **B 两份短文件，开头写「先照 `roles/engineer.md` 做，下面是不同的地方」** | 共同规则只有一份，不会漂移。两份新文件很短 | **它做不到。** 子 agent 跑在**用户的仓库**里，而 `roles/engineer.md` 在安装好的 npm 包里（`package.json` 的 `files` 带 `roles`），**不在用户的工作目录里**。一条 `roles/engineer.md` 的相对路径在那里解析不出东西。这正是 `docs/qa/T-01/case-16-no-internal-pointers.mjs` 钉住的那条教训——提示词随包发出去，**不许指向本包内部**。而且用户可以用 `rolesDir` 只覆盖其中一份（`host/roles.js:158`），那时候「照 engineer.md 做」指的是谁的 engineer.md 都说不清 |
| **C 一份文件写两节，两个角色挂同一份 persona** | 一份文件，一次维护 | **它取消了这套东西的全部意义。** A 会读到 B 的规则，B 会读到「测试文件长什么样」——而 CRD 0013 的第 3 条（B 读不到测试）之所以从自觉升级成强制，靠的就是 B 手里什么都没有。把两半写在同一份提示词里，等于在提示词层面把刚拆开的东西又粘上。而且 `verify-mount.mjs` 按 `personaFile` 逐个检查，一份文件两个角色会让「只跟 PM 说话」这类检查失去指向 |

## 决定

**选 A：三份文件，各自写全。**

**共同规则的漂移，用一件事顶住**：三份文件里凡是**必须**一字不差的句子，由 QA 用例 grep
（`docs/qa/T-53/`、`docs/qa/T-54/`、`docs/qa/T-55/`）。这个仓库已经做过两次同类的事——
`tools/verify-mount.mjs` 里那两个散文钉子（`the tree was moving`、`Parallel by default`，
见 `ADR 0004`、`ADR 0007`），并且明写着这种钉子**故意是脆的**：正当的改措辞要在同一个提交里
同时改提示词和钉子。这次沿用同一个交易，不发明新机制。

## 代价，写清楚不藏

- **三份拷贝真的会漂移。** grep 只钉住被点名的那几句，没被点名的共同规则会慢慢长歪。
  这是选 A 换来的账，不是可以忽略的。
- **改一条共同规则的成本从一个文件变成三个。** 加上一份 grep 用例。
- **两份新文件都会不短。** M1 只要它们超过 500 字符（`verify-mount.mjs` 的检查），
  M3 写实之后大概各一百多行。`roles/*.md` 这一堆会明显变大。
