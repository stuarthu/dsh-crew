# ADR 0022：并行波次里，engineer 不跑 `npm test`——PM 每波跑一次

## 在决定什么

本作业第 1 波要 **10 个 engineer 同时开工**（T-64、T-70 到 T-78），每人改一个不同的文件。
它们**共用一棵工作树**（`main`，没有分支——这个仓库前四件作业都这么干）。

问题是：`roles/pm.md` 的 DoD 和 `docs/design/tasks.md` 里每一个任务行的 DoD 都写着
「`npm test` 全绿」。可是 `npm test` 的第三道检查 `tools/verify-mount.mjs` **一次读进全部九份
角色提示词**，并且对每一份都有自己的断言（两张文件名清单、shell 角色清单、每个角色的 deny 列表
和它的持久化文件）。第五道 `bash docs/qa/run-all.sh` 也一样，193 条用例里有几十条读的是
`roles/` 下的文件。

所以：T-70 改完 `roles/architect.md` 跑 `npm test` 时，T-71 可能正写到 `roles/engineer.md`
的一半。那次 `npm test` 会红，**红在 T-70 没碰过的文件上**。

这不是假想。`roles/pm.md` 自己第 9 步就写着这件事：

> Two engineers running the project's test command in the same working tree can fail on each
> other's half-written file. So serialize those runs, or give one engineer its own working tree,
> and never send an engineer to fix a bug that a moving tree invented.

`principles.md` 原则 18 记着这个仓库为它红过两次。所以规则是有的，它只是**没有说这一波该选哪一个**。

## 桌上的选项

### 选项一：每个任务一棵 `git worktree`（这个仓库自己的现成机器）

`CRD 0013` 为双人形状定的正是这个：一个任务两棵树，`git worktree add`，加上那两条软链接命令
（`CLAUDE.md` 的 **Commands** 一节写着，因为新树的 `node_modules` 是空的，
`verify-mount.mjs` 会**出声跳过**它的角色工具那一半，跑出一个「看起来是绿的」的弱化结果）。

- **好处**：每个 engineer 真的能拿到一个干净的 `npm test` 绿，DoD 那句话不用改一个字。
  隔离是真的，不靠好意。
- **代价**：10 棵树要建、10 次合并要做。它们改的文件互不重叠，所以合并冲突的概率低——
  但**不是零**，而且一次我做错的合并会**丢掉一个 engineer 的全部工作**，
  而丢掉这件事在这个仓库里发生过（`docs/design/tasks.md` 里 T-03、T-04、T-20 三行写着
  「已丢失」）。
- **另一个代价**：新树里 `verify-mount.mjs` 跑的是**弱化版**（缺 symlink 就跳过角色工具那一半），
  所以「我在自己树里绿了」这句话比它听起来弱。要靠那两条软链接命令补，而**忘了加链接不会红，
  只会静静地少查一半**——这正是这个仓库最怕的那种失效。
- **为什么它输了**：它买到的东西（每个 engineer 一句自己的「绿」）比它的风险小。
  这一波九个任务改的是**散文**，每一份的真正判据是「我这个文件里那几句话在不在」，
  而那件事有一条**只读我自己文件**的命令能查（见选项三）。为了一句更漂亮的绿，
  换来 10 次合并和一个「丢工作」的真实先例，不值。

### 选项二：把这一波串起来，一个一个跑

- **好处**：一行改动都不用，规则照旧。
- **代价**：这一波是九份角色提示词，architect 实测同类 engineer 一轮 2 到 17 分钟。串起来是
  **小时级**，而本作业的整个目的是快（PRD 的问题一）。
- **为什么它输了**：它直接违背本作业自己要落地的第 1e 项（一个改动一个 engineer，并行），
  而 `roles/pm.md` 第 9 步已经写明「Never serialize to save agent count」。
  为了避免一个假红而串行，是用小时换分钟。

### 选项三：engineer 只跑读自己文件的那条命令，`npm test` 由 PM 每波跑一次（**推荐**）

每个 engineer：

- **可以**跑它自己那一条（或几条）新用例文件，直接 `node docs/qa/T-70/case-01-....mjs`。
  一条用例读的是**它自己那一个角色提示词**，所以别人的半成品碰不到它。这就是它的「先红后绿」。
- **不许**跑 `npm test`，也不许跑 `node tools/verify-mount.mjs` 或
  `bash docs/qa/run-all.sh`——这三条会读进别人正在改的文件。
- 如果它无论如何看到一条红，而红在**它没有的文件**上，规则是：**报，不修。**
  `roles/pm.md` 第 9 步的原话是 `never send an engineer to fix a bug that a moving tree
  invented`。

PM 在**整波交工之后**跑一次 `npm test`，在一棵没人在写的树里。红了就把真实的错误文本发给
拥有那个文件的 engineer。

- **好处**：假红的路被完全堵住（三条会串味的命令一条都不跑），而每个 engineer 仍然有一条真的、
  能红能绿的检查。没有树要建，没有合并要做。而且它和本作业自己要落地的形状一致——
  第 1b、1c 项就是「把检查批到最后」。
- **代价，写下来不藏**：
  1. **一个 engineer 交工时，不知道自己有没有破坏别的文件的检查。** 那件事推迟到 PM 那一次跑。
     所以一个 engineer 的「done」比旧形状弱：它证明的是「我那几句话在了」，
     不是「整个仓库还是绿的」。
  2. **两个 engineer 的改动互相打架时，只有 PM 那一次跑会发现**，而那时两边都已经交工。
     这一波九份角色提示词各自独立，所以概率低；但 T-64 同时改
     `roles/pm.md`、`tools/verify-mount.mjs` 和 `host/crew.js`，它和别人相撞的机会比别人高。
  3. **每个任务行的 DoD 里那句「`npm test` 全绿」，验的人从 engineer 变成 PM。**
     这不是把标准改弱——那句话仍然要为真才算做完——但**谁来验**换了人，
     所以它必须写在这里，不能只活在简报里。
- **为什么它赢**：它是唯一一个既不花小时、又不建十棵树、还让每个 engineer 手里有一条真能变红的
  检查的做法。它承认的那件事是真的：这一波的工作是散文，而散文的钉子只读一个文件。

### 选项四：让 engineer 跑 `npm test`，红了自己判断是不是别人弄的

- **为什么它输了，而且输得最难看**：它把「这条红是我的吗」这个判断交给一个**看不见另外九个人的
  角色**。它没有任何办法查证，所以它只能猜。猜错往哪边都坏：当成别人的，就漏掉自己真的破坏；
  当成自己的，就去改一个它不拥有的文件，撞上「只碰你拥有的文件」那条硬规矩。
  `roles/pm.md` 第 9 步那句 `never send an engineer to fix a bug that a moving tree invented`
  就是在禁这一个。

## 决定

**选项三。** PM 决定，2026-08-21。

理由一句话：这一波的产物是散文，散文的真正判据只读一个文件，所以不需要隔离整棵树就能拿到
真的「先红后绿」；而剩下那半（全库还绿不绿）本来就该批到最后，那正是本作业自己在落地的形状。

## 后果

- 第 1 波十份简报里各写一段：**你可以跑哪条命令、不许跑哪三条、看到不属于你的红怎么办。**
- PM 在整波交工之后跑一次 `npm test`，并在里程碑报告里给出真实数字。
- 每个任务的 Verdicts 行照 `CRD 0020` 写真话；`npm test` 这一项由 PM 验，写在这份 ADR 里。
- **这条决定只管并行波次。** 串行链上的 T-65、T-66、T-67 一次只有一个人在写
  `roles/pm.md`，所以那三个任务**照旧自己跑 `npm test`**，拿真的全绿。
  这份 ADR 不改它们一个字。
- 本作业结束时，这条决定要么进 `principles.md`（如果它该成为一条规则），要么留在这里。
  PM 在第 18 步的搬运里判。**先记在这里，免得它跟着作业文件夹一起消失。**
