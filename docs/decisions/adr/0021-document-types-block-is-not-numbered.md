# ADR 0021：A6 那份「八种文档各装什么」的清单在 `principles.md` 里放成什么

- **状态**：已采纳（推荐），2026-08-21
- **决定人**：crew architect。用户说的是「websearch 之后写进 `principles.md` 和写它的那个角色的
  提示词」（`CRD 0023` 决定六），**没有说写成什么形状**。所以形状是我的选择，是 ADR。
- **落在哪里**：T-63（`principles.md` 的长版）、T-67 / T-70 / T-72 / T-77（各角色的短版）。

## 在决定什么

A6 要把八种文档「装什么」写进 `principles.md`：PRD、HLD、ADR、CRD、接口契约、
测试计划与用例、发布与升级计划、DoD。依据是 `docs/research/document-types.md`，每条带出处。

`principles.md` 今天有 **21 条编号原则**，加上三节不带编号的内容
（`## Words we use`、`## What we looked at and did not take`、`## Keeping this file honest`）。

**要决定的是：这八种文档的清单是第 23 条原则，还是一节不带编号的内容，还是别的什么。**

（为什么是 23 不是 22：A4 会用掉 22。）

## 为什么这个选择值得写下来

因为**编号在这个文件里是有代价的**。七处地方按号引用它：
`CLAUDE.md` 写着「`principles.md` 8, 13, 14, 15, 19 and 20」，
`principles.md` 自己有一处按号引用，还有几份 CRD 和 ADR。
`docs/qa/T-52/case-01` 专门钉住「编号是 1 到 21，不多不少」，
理由写在它自己的头部注释里：插进一条或重排一条，**七处引用同时变错，而没有任何检查会红**。

本作业已经要动那个编号集合一次了（A4 加 22）。**动两次的风险不是一倍，是两倍**，
而且第二次动的东西是一份参考清单，不是一条规则。

## 桌上的每一个选项

### 选项 A（**推荐**）：一节不带编号的内容，紧跟 `## Words we use`

- **是什么**：`## What each document holds`（或中文标题的等价物），
  八个小节，每节一条「装什么」的清单加出处。位置紧跟已有的 `## Words we use`，
  因为那一节也是「参考」，不是「规则」。
- **好处**：**这个仓库已经为完全同一个问题做过完全同一个决定。** `ADR 0014` 定的就是
  用词表不做成 `## 22.`，而做成一节不带编号的内容；`case-01` 里那半句
  「the glossary must NOT become `## 22.` (`ADR 0014` option B, rejected)」就是它的钉子。
  八种文档类型和用词表是同一种东西：**读的时候查，不是干活的时候遵守。**
- **代价**：不带编号，就没法被别处按号引用。要引用只能按标题名字引。
- **以后会在哪里疼**：`principles.md` 的不编号部分会越长。今天三节，之后四节。
  某一天它长到需要自己的目录。那一天再拆，不是今天。
- **为什么它没输**：它是唯一一个不再动那个被七处引用的编号集合的选项，
  而且它有一个一模一样的先例。

### 选项 B：编号原则 23

- **是什么**：`## 23. Each kind of document holds a known set of things`。
- **好处**：编号让它显得同等重要，也让别处能按号引用。
- **代价**：第二次动编号集合。`case-01` 的断言要第二次改（第一次是 A4 的 22），
  「1–21」那个范围要改成「1–23」，`CLAUDE.md` 里那句按号引用要重读一遍。
- **以后会在哪里疼**：一条**原则**是「一条要遵守的规则」，
  而这八节是「PRD 该有哪几节」这种参考内容。把参考内容编成原则，
  下一次有人问「原则 23 要我做什么」的时候答不出来——因为它不要求你做什么。
- **为什么它输了**：它付的是编号的代价，买的是一个它不该有的身份。

### 选项 C：八块各自并进已有的原则里

- **是什么**：PRD 那块并进原则 20（那条有流程表的），契约那块并进原则 2，
  DoD 那块并进原则 20，测试计划那块并进原则 13，发布计划那块并进原则 15……
- **好处**：每条内容都紧贴它所属的规则，不新增任何东西。
- **代价**：八块散进六七处，**没有人能一次读完**。
  而 A6 要的正是「一份清单」——用户的原话是让 PM 知道**怎么正确地写一份 PRD**，
  那需要一处能一口气读完的地方。
- **以后会在哪里疼**：原则 20 已经是这个文件最长的一节。再往里塞两块，
  它会变成一个没人读到底的段落。
- **为什么它输了**：它把一份要被当清单用的东西，拆成了六块背景资料。

### 选项 D：单独一份文件 `docs/design/document-types.md`

- **是什么**：不进 `principles.md`，自己一份。
- **代价**：`principles.md` **不随 npm 包发布**，而 `docs/` 下的文件也不发布——
  所以这一条不是它输的理由。真正的代价是：
  ① 用户明确说「write it in principle and pm role.md」，落点是指定的；
  ② 又多一个装规则的地方，而这个仓库刚刚用 `CRD 0006`、`CRD 0007`、`CRD 0008`
  三份 CRD 把「什么东西住在哪」收拢过一遍。
- **为什么它输了**：落点是用户指定的，而且它逆着这个仓库刚做完的一次收拢。

## 推荐

**选项 A：一节不带编号的内容，紧跟 `## Words we use`。**

一句话：**它是一份查阅用的清单，不是一条要遵守的规则；而这个仓库上一次遇到
一份查阅用的清单时（用词表，`ADR 0014`），做的正是这个决定。**

## 顺带定下的两件事

### 一、先非编号，后编号

T-63（这一节）排在 T-68（原则 22）之前。理由：T-63 只加不带编号的内容，
**完全不碰那个编号集合**，所以它交工时 `docs/qa/T-52/case-01` 仍然是绿的。
反过来（先加原则 22）也能做，但那样 `case-01` 在链的第一环就红了，
第二环还要在一个已经红的文件上干活——**红的基线上分不清新红和旧红**
（`roles/engineer.md` 的「A false red is not evidence」讲的正是这个）。

### 二、这一节要放在 `## Words we use` 的**后面**，不是前面

`docs/qa/T-52/case-09-glossary-placement.mjs` 断言 `## Words we use` 是
**紧跟原则 21 的下一节**。把新的一节插在原则 21 和用词表之间，那条用例立刻红。
放在用例表之后（在 `## Words we use` 和 `## What we looked at and did not take` 之间），
`case-09` 三条断言全部照旧成立。

**T-68 加原则 22 时那条用例还是会红**——因为原则 22 会插到原则 21 和用词表之间，
用词表得跟着挪到最后一条原则之后。那是 T-68 的一格 DoD，见 `ADR 0018`。
