# ADR 0005：删分支的窗口只收窄到「一轮对话」，不用 lease 关死

## 背景
第 17 步的第三个证明读的是**远端**分支：`git branch -d` 保护本地分支，远端分支没有任何东西
保护。但证明和真正的删除之间总有一段时间，用户在这段时间里思考、回答。如果这期间有人往
远端作业分支上推了一个提交，三个证明全部通过，那个提交连着分支一起被删掉。所以要选：这段
窗口怎么处理。

## 选项
- **A** 在用户说「是」的**同一轮对话里**把第三个证明再跑一遍——`git fetch <remote> --prune`，
  然后 `git log --oneline main..origin/crew/<job-slug>`——只有再次无错且无输出才删。代价：
  窗口从十分钟收窄到几秒，但**没有关死**。
- **B** 用 lease 形式的删除：`--force-with-lease=<ref>:<sha> :<ref>`。它是**原子**的，能真正
  关死这个窗口。代价：这一步里「永远不 force」就从一条平的规则变成「永远不 force，除了
  这里」。

## 决定
选 **A**。**这一条是用户的决定**：PM 把这个取舍讲清楚了——git 的分支删除没有 lease，所以
唯一的原子形式就是 lease 式的 force——用户听完之后选了那条平的规则。理由是一条带一个例外
的规则会被磨掉：以后没人记得例外的边界在哪，「永远不 force」就不再是一句能照着做的话。

代价必须写在明面上，而不是装作没有：**剩下这几秒是整个功能里唯一还能弄丢工作的地方**。
窗口从十分钟收窄到一轮对话，是收窄，不是关闭，而且是故意的。

## 谁要求的
**选择是干活时撞上的，决定是用户做的。** crew 在写第 17 步的删除证明时发现了这个窗口，
没有人事先要求处理它；把取舍摆到用户面前之后，是用户选了 A。所以按「有人要求过吗」的判据
它仍然是 ADR 而不是 CRD——没有人要求过这件事，它没改变范围也没改变契约。
