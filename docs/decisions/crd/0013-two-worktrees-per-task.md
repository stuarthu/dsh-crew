# CRD 0013：一个任务两棵工作树——把「A 先跑一小段」换成真隔离

## 谁提的

用户，2026-08-21，在 `CRD 0012` 被 accept 之后、任何代码开始之前。原话：「can we let test engineer
and code engineer work on different branches so their work don't interrupt each other? this is to
eliminate the requirement to run a for a short period then run b」，随后自己补准了名字：
「or maybe called working tree」。

## 他们要什么

A 和 B 各自在**自己的一棵 git 工作树**里干活（`git worktree add`，两个真实目录，各 checkout
一个分支），从而**取消 `CRD 0012` 第 2 条那个「A 先跑一小段，B 再开工」的串行头**。

**说准一件事**：光换分支做不到。`git switch` 动的是同一个工作目录，两个 agent 不可能同时待在两个
分支上。要的是工作树。

## 为什么

`CRD 0012` 第 2 条是为了躲一个竞态：A 在共享的工作目录里跑自己的测试时，B 正在同一个目录里写代码，
所以 A 那一次运行可能撞上三种状态，其中一种是**假红**——长得和真红一样。第 2 条用「让 B 等一会儿」
换掉那个竞态，代价是丢掉一部分并发。

两棵工作树把竞态从根上去掉：**B 的代码在 A 的树里从来不存在**。

## 它买到三样东西

1. **A 和 B 真的同时开工。** 串行头没了。
2. **`CRD 0012` 第 3 条从自觉变成强制。** B 的树里**没有那个测试文件**，它不是「不该读」，是
   **读不到**。原来那一条明写着「靠自觉，读一个文件不留痕迹，事后查不出来」，是一条安全带。
   现在在写代码阶段它是一道**锁**。
   **这关掉了 `CRD 0012` 里被标成「没有机制能做到」的那个洞**，而且用的是普通 git，不是平台功能。
3. **A 的红灯永远干净。** 那三种状态的竞态消失。

## 更正一句 PM 说过的话

PM 在访谈中把 worktree 隔离否掉，理由写成「平台层的活，crew 今天完全没有 worktree 的概念」。
**这句话对错了一半，收回一半**：dsh-crew 要有一个 worktree *功能*，那才是平台活；但**PM 用普通
`git worktree add` 开两棵树，不需要任何平台功能**——PM 本来就是唯一碰 git 的角色（这是 crew 的硬
规则）。`CRD 0012` 否决表里那一行因此只在「做成产品功能」这个意义上成立。

## 定下来的六条

1. **每个任务两棵工作树。** PM 用 `git worktree add` 开，A 一棵、B 一棵，各自一个分支，从同一个
   基点长出。PM 开，PM 合，PM 清。engineer 不碰 git（crew 硬规则不变）。
2. **`CRD 0012` 第 2 条删除。** A 和 B 同时开工。A 在自己的树里写测试并跑一次拿红灯；B 在自己的
   树里闭眼写代码。互不干扰，不是靠约定，是靠两个目录。
3. **`CRD 0012` 第 3 条升级为强制**——在写代码阶段。B 的树里没有测试文件。
4. **`CRD 0012` 第 5 条移动。** B **跑不了** A 的测试（不在它的树里）。**首次会合的那一次运行发生
   在合并之后，由 PM 跑。** 这是净收益：PM 手里本来就同时有两半（`CRD 0012` 第 14 条要它把这份
   输出交给 code reviewer），而「失败的断言消息会泄露测试内容」这个顾虑对 B 彻底消失。
5. **合并后那次运行是红的，B 回到合并后的树里修**（用户在两个选项里选了这个）。
   **独立性到修的那一刻结束，这是明知故犯，写在这里不藏**：B 的独立读法已经在合并前落定并留了
   记录，那份证据已经拿到手；之后还硬把它蒙住，只会让修 bug 变难，换不到新的信号。
6. **任务行必须把文件清单拆成「A 的文件」和「B 的文件」，两边不许重叠。**
   **一个任务如果它的测试和代码必须动同一个文件，它就不能用双人形状。** 这是 PM 不推荐双人的
   第五个理由，接在 `CRD 0012` 第 13 条那四类后面。

## 一个会安静出错的地方——必须写进流程

新开的工作树里 `node_modules` 是空的。这个仓库特别便宜：**`dependencies` 和 `devDependencies`
都没有**，只有一条 `peerDependencies`，而 `node_modules/` 里只有一个东西——那条软链接。所以一棵
工作树要跑全量 `npm test`，只要两条命令：

```sh
mkdir -p node_modules/@deepseek-ai
ln -s ~/.dsh/profiles/node_modules/@deepseek-ai/dsh-tool-subagent \
      node_modules/@deepseek-ai/dsh-tool-subagent
```

**少了它不会报错，会安静地变弱**：`tools/verify-mount.mjs` 会出声跳过 role-tool 那一半，工作树跑
的是一套更弱的检查，而且看起来是绿的。这正是 `CLAUDE.md` 说的「绿色 CI 的意思是公开 runner 能查
的都查了，不是全都查了」的同一个坑，只是搬到了本机。所以这两条命令是 PM 开树流程的一部分，不是
提醒。

## 代价

- **墙上时间变好**，因为串行头没了。`CRD 0012`「代价」一节那句「墙上时间可能更短」现在更站得住。
- 力气那个 35%–75% 的估计不改，另加每个任务两次 `git worktree add`、两条软链接命令、一次合并、
  两次 `git worktree remove`。每一步几秒。
- **git 垃圾**：忘了清理就会攒下工作树和分支。这是 PM 的活，要写进流程。
- **一条新的硬约束**：文件拆不开的任务不能用双人形状。这会让双人形状能用的范围变小，是真实的代价。
