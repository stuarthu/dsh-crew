# CRD 0001：修掉 git guard 的 `push-ok` 子串误判

## 谁提的

用户，在第 1 轮评审报告出来之后。

## 想要什么

用他的话：「fix the git guard push-ok bug too」。

即：本次作业除了给 PM 加合并与清理步骤，还要修掉安全评审在
`host/git-guard.js` 里发现的那个 pre-existing 问题。

## 为什么

`host/git-guard.js` 第 202-204 行用
`command.includes(basename(approvalFile))` 做匹配，而且这段检查在第 208 行的
「信任 root 会话」之前执行。后果：任何命令文本里只要出现 `push-ok` 这个子串，
连用户自己的会话都会被整条拒掉。

一个叫 `crew/push-ok-flow` 的作业分支，会让新加的第 17 步里每一条 git 命令都被
挡住——合并、推送、删除全部走不通，而且报错说的是「你碰了审批文件」，和真实原因
完全无关。这正是新功能会踩到的坑，所以和本次作业直接相关。

## 会动到什么

- `docs/crew/dod.md`：「不做的事」里「不改 `host/` 下的任何代码」这一条要改，
  并新增任务 T-05 和验收检查 18-21。
- 新任务 T-05：`host/git-guard.js`、`tools/verify-guard.mjs`。
- T-04（CHANGELOG）多写一条修复说明。
- 不动 T-01 正在做的两个文件；T-01 仍然不许碰 `host/`。

## 代价

不用重做任何已经完成的工作。T-01 的修复轮正在跑，它拥有的文件和 T-05 拥有的
文件没有重叠，所以两者可以并行，不需要打断。

风险：`host/git-guard.js` 是安全中间件，改错了会让保护失效。所以 T-05 必须
测试先行，并且要有两类用例——「以前误挡、现在必须放行」和「以前挡对、现在必须
继续挡住」。已有的第 68-69 行和第 166-168 行用例一条都不许改成绿。

## 决定

accepted。用户决定（他直接要求做这件事）。范围变更由用户拍板，理由见上：这个
bug 会让新写的第 17 步在某些分支名下完全不可用。

## Applied

`docs/crew/dod.md` 版本 4。
