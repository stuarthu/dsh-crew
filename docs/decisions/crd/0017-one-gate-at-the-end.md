# CRD 0017：剩下四个里程碑合成一个，只在最后一次评审

## 谁提的

用户，2026-08-21，在 M1 的里程碑评审之后。先问「how many milestones left」，再问
「can we merge them into 1」，PM 给了分析和一个折中建议（两道门），用户的决定是
**「only 1 gate at last, and review only at last」**。

## 他们要什么

**原来的 M2、M3、M4、M5 合成一个里程碑。用户只在全部做完时被问一次。**

## PM 反对过，理由记在这里，因为它是这次决定的代价

PM 建议的是**两道门**：T-52 交工时一道，最后一道。理由是
**`principles.md`（T-52）是后面每一个任务引用的源文件**：

| 任务 | 引用它的什么 |
| --- | --- |
| T-53 / T-54 | 两份 persona 的行为规则要和原则 21 对得上 |
| T-57 | `roles/code-reviewer.md` 要写「全绿不等于文档清楚」那个反转 |
| T-59 / T-60 | 两份 README 和 `CLAUDE.md` 要放三角色对照表 |

**所以：如果用户读完原则 21 说「这不是我的意思」，在 T-52 那个点上代价是一个任务（18 条 DoD）；
放到最后才发现，代价是 T-52 加两份 persona 加 `roles/pm.md` 加 `code-reviewer.md` 加两份 README
加 `CLAUDE.md`——因为它们全是照着它写的。**

**用户听过这条并重申了决定。这一节不是异议，是把代价写下来，好让它以后不会变成「没人提醒过」。**

## 合并不换来速度，这一点也要写清

PM 查过任务行里的 `依赖` 字段：**任务级的依赖已经把顺序锁成和原来的里程碑一模一样**——
`T-52 → (T-53‖T-54‖T-55) → (T-56‖T-57‖T-58) → T-62 → (T-59‖T-60‖T-61)`。
该并行的本来就并行，该串行的是**任务依赖**在管，不是里程碑边界在管。

**所以本 CRD 省下的是三次「停下来问用户」，不是任何墙上时间。** 用户要的正是这个。

## 定下来的

1. **里程碑列表从五个变成两个**：`M1`（已完成）和 `M2 — 其余全部`。
2. **用户的里程碑评审只在 `M2` 全部做完时发生一次。**
3. **crew 内部的四道门一个不减**：每个任务照旧走代码评审、安全评审（按风险判断）、QA，
   文档评审照旧在文档改动之后跑。这些不占用户的时间，而且 T-51 证明了它们真的会抓到东西
   （文档评审两轮 11 条 blocking、安全评审一条 blocking、QA 三轮）。
4. **原来那四个里程碑的名字保留成「阶段」，写在任务行的里程碑字段里**，例如
   `M2（阶段 2/4：persona 写实，原 M3）`。理由：那四组分法**就是依赖图**，它是有用的信息；
   而如果任务行继续写 `里程碑：M3` 而 PRD 里已经没有 M3，那就是一个**指向不存在的东西的指针**
   ——这个仓库已经因为同样的毛病吃过一次大亏（四份 CRD 至今指着没有任何文档定义的检查编号，
   `CRD 0010` 记着这件事）。
5. **PRD 各阶段原来的 DoD 一条不删。** 合并的是评审的时机，不是验收的内容：134 条 DoD 照旧要满足。

## 它动到什么

| 文件 | 动什么 |
| --- | --- |
| `docs/design/prd.md` | 里程碑那一节：五个变两个，四组保留成阶段；版本升到 8 |
| `docs/design/tasks.md` | 11 个任务行的**里程碑字段**改成 `M2（阶段 n/4：…，原 Mx）` |
| `~/.claude/crew/jobs/paired-engineers/state.json` | `milestones` 数组 |

## 代价

- **上面那一节：源文件写错的发现点从「一个任务之后」推到「全部之后」。** 这是本 CRD 的主要代价。
- 一次机械改动：11 个任务行的一个字段。
- **省下三次停下来问用户。** 这是用户要的东西。

## 决定

**accepted。用户决定，2026-08-21，原话「only 1 gate at last, and review only at last」。**
PM 反对过（两道门），用户重申，PM 按用户的决定执行。

## Applied

`docs/design/prd.md` v8、`docs/design/tasks.md` 11 个任务行的里程碑字段、`state.json` 的
`milestones` 数组。**没有任何 DoD 条目因本 CRD 增减。**
