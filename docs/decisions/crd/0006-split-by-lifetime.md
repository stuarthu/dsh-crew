# CRD 0006：按「活多久」分家——决定进仓库，一次性的进作业文件夹

## 谁提的

用户，在本次作业的代码和文档都落地之后的一段对话里。他连着提了四个问题：QA 用例该不该
进项目自己的测试目录、CRD 该不该放在产品仓库里、DoD 该不该是临时的、运行结果该不该丢掉；
然后自己收敛出了形状，并在「按大小分家还是按种类分家」上听完反驳后选了按种类。

## 想要什么

**按「活多久」分家，不按「谁在场」也不按「活多大」分家。**

**进仓库，持久：**

- **ADR** —— 「怎么做」的决定，**不分活的大小**。小活没有架构师，所以由 **PM 写**。
  ADR 不需要架构师存在，它需要**决定**存在。
- **CRD** —— 「做什么 / 范围 / 契约」的决定，**不分活的大小**。
- **QA 的用例** —— 会一直跑的可执行资产。

**进作业文件夹（`~/.dsh/crew/jobs/<job>/`），一次性，验完就丢：**

- **DoD** —— 它列的验收检查，在全部变成真的那一刻就成了历史。
- **QA 的测试计划** —— 用例一写出来，计划的任务就完成了；那张「检查 → 用例」的表，
  用例本身已经用可执行的形式装了同样的信息。
- **运行结果** —— 现在本来就不落盘（输出只走 stdout），把它写成规则。

**收尾时必须有一个搬运动作。** 一次性文档删掉之前，里面持久的东西必须先搬出去：

- 规则 → `principles.md`；
- 「怎么做」的决定 → 一份 ADR；
- 范围 / 契约的决定 → 一个 CRD；
- 这一次改动的理由和当时的测试数字 → 提交信息（快照断言，不是需要维护的文件）；
- QA 计划里「测不到什么、为什么」那一段 → 一份常备的可测性缺口清单。

「不需要了」必须是**挣来的**，不能是假设的。

## 为什么

1. **现在的规则按「谁在场」分家。** 「PRD 类写 ADR，小活写进 `docs/crew/dod.md` 的
   Decisions 小节」——决定的落脚处由「有没有架构师」决定，而不是由「这是什么东西」决定。
   这是设计上的将就。
2. **按活的大小分家会把同一个毛病再犯一次。** 以后有人问「为什么这个检查放在这一层」，
   他得先知道当初那件活是大还是小。而且 CRD 和 ADR 的形状根本不通用：CRD 全是围绕「已经
   说定的东西要改」（谁提的、范围、代价、要不要用户点头），一个「修这个 bug 有两种写法」
   根本没人提出要求，也没改变用户拿到的东西。
3. **反证就是本次作业**：它是**小活**，却写了 5 个 CRD（0001-0005），全是真的范围变更、
   全要用户点头。如果小活的 CRD 位置被设计决定占了，这五个就没地方去，同一个文件夹里
   会躺着两种意思完全不同的文件。
4. **DoD 是「作业进度」穿了一件文档外衣。** `state.json` 本来就在仓库外（`CLAUDE.md` 的
   理由：让用户的 `git status` 保持干净），DoD 属于同一类。
5. **位置对 agent 没影响**：本次作业给每个 agent 的都是绝对路径，DoD 在
   `docs/crew/dod.md` 还是在作业文件夹里，它们读起来一样。

## 会动到什么

- `roles/pm.md`：第 4 步（写哪种文档、写在哪里）、第 10c 步、第 11 步（提交什么）、
  第 16 步之后的收尾，加上新的「搬运」动作。
- `roles/qa.md`：计划写到作业文件夹；用例仍然进仓库；`roles/qa.md:38` 那句「PM 提交你的
  计划和用例」改成只提交用例。
- `roles/engineer.md`、`roles/architect.md`、`roles/doc-reviewer.md`：把「小活写 DoD 的
  Decisions 小节」换成「小活也写 ADR，由 PM 写」。
- `principles.md`：第 13 条（测试落盘）、第 14 条（文档是唯一通道）、第 17 条
  （谁发现选择、谁不独自决定）要跟着改；可能需要新增一条讲「按活多久分家」。
- `CLAUDE.md` 的 State and documents 一节。
- `README.md`、`README-zh.md`、`CHANGELOG.md`。
- 把 `docs/crew/dod.md` 和 `docs/crew/qa/*-plan.md` 从仓库里移走。

## 代价与协调（这一条最要紧）

**上面有五个文件是另一个会话刚刚交付的东西。** `dsh-crew-09` 在 `bfdc799` 里立的正是
「小活写 DoD 的 Decisions 小节」，写在 `roles/engineer.md`、`roles/architect.md`、
`roles/doc-reviewer.md` 里，加上它随后写进 `principles.md` 的 `## 17` 和
`roles/pm.md` 的那段。本 CRD 会**替换掉它刚立的那条规则**——不是它做错了，是用户在它
交付之后想清楚了更好的形状。

它明确说过它读不了本会话的回复，所以**用户是唯一的通道**。

**因此：本 CRD 的执行被挂起**，等 `engineer-proposes-fixes` 那件作业收尾之后再做，一次
把两条规则对齐。现在就动手会造成两个会话在同一批文件上对着改。

## 修订：ADR 的选项由谁供（2026-08-20，执行之前）

原文写「小活没有架构师，所以由 **PM 写**」。用户问了一句更好的问题：小活是不是也该叫
架构师来写 ADR？

**他的提法的硬核是对的**：决定的人不该独自写记录。但补位的人不是架构师，因为
**选项本来就不是架构师供的**——`bfdc799` 立的规则是：工程师修 bug 时先找出至少两种做法，
把原因、每一种做法、各自的代价和以后会疼在哪、以及它推荐哪一个，写进 `Q-` 文件。ADR 里
最值钱的那一节，来源已经是离代码最近的那个人，而且**不是做决定的人**。

派架构师去，它实际做的是把工程师的 `Q-` 文件加 PM 的决定抄成 30 行，代价是一次 agent
往返，还要把工程师已经汇报过的东西重新讲一遍。

**决定（用户选的 C）**：

- **ADR 的「选项」一节，原文引用工程师 `Q-` 文件里的内容**，不重写、不概括。
- **PM 只补两节：「决定」和「理由」。**
- 权力照样分开：选项不是 PM 写的；而且因为是引用，PM 没法悄悄把选项改成对自己的决定
  有利的形状。
- 不多花一个 agent。

**没有被批准的**：PM 曾建议「决定大到值得第二次阅读时叫架构师复核」作为 C 的备选。
用户只选了 C，所以**那条不在规则里**。要加需要他另外一句话。

**时机**：本 CRD 的规则那一半还没执行，角色提示词里一个字都没改，所以这次修订成本是零。

## 修订二：`Q-` 文件的寿命，以及 ADR 必须引用而不是指向（2026-08-20）

用户问：「but where is this q file land?」

**答案**：`<job folder>/inbox/Q-<number>.md`，也就是 `~/.dsh/crew/jobs/<job-slug>/inbox/`，
**在仓库外面**，和 `state.json` 同一个文件夹（`roles/pm.md:55`、`roles/engineer.md:175`、
`roles/qa.md:116`、`roles/architect.md:175`）。

**所以这是本 CRD 的一个真缺口**：修订一说「ADR 的选项原文引用工程师的 `Q-` 文件」，
而按本 CRD 的分家，那个文件夹装的正是一次性的东西，作业结束就丢。选项的来源会消失，
而 ADR 是那个该永久留下的文件。

**补两条规则：**

1. **`Q-` 文件是一次性的**（作业文件夹，随作业丢掉），和 DoD、QA 的测试计划、运行结果
   同一类。本 CRD 原文没给它定寿命，现在定了。
2. **ADR 必须「引用」，不能「指向」。** 选项一节里要有工程师写下的原文，**不许**写成
   「选项：见 Q-03」。理由就是第 1 条：那个文件会消失，而指针指向一个消失的文件，等于
   把 ADR 最值钱的一节删掉。这条要写进 `roles/pm.md`，因为写 ADR 的是 PM。
3. **`Q-` 文件的答复，如果改了任何规则或文档，属于持久的那一半**，必须在文件夹被丢掉
   之前搬出去——就是本 CRD 的「搬运」动作。

**本次作业是活证据。** `inbox/` 里有两个 `Q-` 文件：

- **Q-19** —— 工程师问「CRD 0007 里的旧路径是记录还是指针」。答复让验收检查 67 收窄，
  并写进了 DoD。
- **Q-20** —— 工程师报「CRD 0006 和 0009 里还没执行的指令指着已经不存在的路径」。答复
  变成了这两个 CRD 末尾的编者注。

两个的内容都活下来了——**但是因为 PM 恰好把答复写进了文档，规则里没有任何一条要求他这么
做**。下一个 PM 可能不会，那两个问题和它们的答案就随文件夹一起消失。

## 修订三：没有 `Q-` 文件的时候，选项引用什么（2026-08-20）

修订一写的是「ADR 的选项一节，原文引用工程师 `Q-` 文件里的内容」。**它假设了 `Q-` 文件存在。**

但 `Q-` 文件只在工程师**被卡住、需要问 PM** 的时候才写。一个在自己范围内做了决定、然后汇报的
工程师**不写 `Q-` 文件**——它把选项写在汇报里。本次作业就是活证据：`T-17` 回填的六份 ADR，
一份 `Q-` 文件都没有（它的来源是提交信息和代码）；`ADR 0007` 的来源是 `T-27` 的汇报。

**补一句**：选项一节引用的是**工程师自己的话**——它问了就是 `Q-` 文件，它在范围内决定了就是
它的汇报。两种都要原文引用，不许 PM 改写或概括；理由和修订一一样：选项不能是做决定的人的话。
