# ADR 0003：临时目录的清理放在整个用例区段外面的一个 `finally` 里

## 背景
`tools/verify-preset-install.mjs` 在四处调用 `mkdtempSync`，一处也没删，所以每跑一次
`npm test` 就在 `/tmp` 里留下四个 `crew-home-*`（发现时机器上堆了 570 个）。修的时候要选
清理放在哪里。

## 选项
- **A** 每个用例结束就删掉自己那个目录。看着最贴近「谁建谁删」，但用例区段里任何一处抛错
  都会跳过后面的删除；而且删得太早的风险要靠人记住——某个断言其实还要读那个目录。
- **B** 用一个 `makeHome()` 帮手记下每个确切路径，整个用例区段包在 `try` / `finally` 里，
  `finally` 只删这些确切路径。多一层缩进，清理离建的地方远一点。

## 决定
选 **B**。`finally` 里只删 `makeHome()` 记下的那些确切路径——没有通配、没有 glob、没有
任何拼出来的字符串，所以它伸不出这次运行之外。抛错的用例的目录也一定会被删。区段末尾另加
两个用例：一个在运行留下任何东西时红，一个证明「抛错的用例的临时目录仍然被删掉」。

**A 的那个风险是测出来的，不是假设的**：把清理挪到断言之前，并不会悄悄变绿——它会
以 `ENOENT` 崩掉并且非零退出。所以选 B 不是因为 A 会静默出错，而是因为 B 只写一处、
抛错也覆盖，而且删除范围被限定在记录下来的确切路径上。本次作业刚好对
`tools/verify-guard.mjs` 提了同一条要求，两个脚本因此形状一致。

## 谁要求的
没有人。这是干活时撞上的选择，所以按「有人要求过吗」的判据，它是 ADR 而不是 CRD。
（「不要漏临时目录」是 QA 发现、用户点头纳入的，记在 CRD 0005；这里定的是「清理放在
哪里」，没有人要求过。）

`tools/verify-preset-install.mjs` 的 `makeHome()` / `removeHomes()` 和那个 `finally`。
