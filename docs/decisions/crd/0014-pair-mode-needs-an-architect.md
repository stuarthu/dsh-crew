# CRD 0014：双人形状只出现在有 architect 的作业里，接口由 architect 钉在 ADR 里

## 谁提的

用户，2026-08-21，在 `CRD 0013` 之后、任何代码开始之前。起因是 PM 报了一个阻塞性的洞（见下一节），
并给了两个都不太好的选项。用户给的是第三个，比两个都好。

原话：「I think before user choose solo or pair mode, pm should first decide whether this task is
big enough for architecture. and let user choose only archi is needed. so pair mode always happen
with an archi. so archi can decide the function signature in adr and let test/code engineer follow
their part」

## 它修的那个洞:撞名字,不是分歧

A 要写出一个测试，必须先决定五件事：从哪个文件 import、导出的名字、签名（几个参数、什么顺序、
什么形状）、返回的形状、出错时的行为（抛异常还是返回空，异常里写什么）。B 要决定同样这五件。

**两个人都只看 DoD 那一节，而且永远看不到对方**（`CRD 0013` 之后是两棵工作树，物理上看不到）。
所以 A 写 `parseRoleTable(rows)`、B 写 `readRoleTable(text)`，首次会合就是红的。

**这个红灯不是分歧，是撞名字。** 而且上面五项里任何一项不一致就红，所以这类噪音的发生率接近
100%——`CRD 0012` 要的那个信号会被彻底淹掉，PM 每个任务都在裁「谁的名字算对」，一次都轮不到
真正的歧义。两棵工作树让它**无法自愈**。

## 定下来的四条

1. **双人形状只存在于有 architect 的作业里。** 小作业那条路（PM 自己写任务行、不起 architect）
   **没有**双人形状。
2. **两层决定，两层今天都已经存在，一条新流程都不加：**

   | 层 | 谁决定 | 什么时候 | 决定什么 |
   | --- | --- | --- | --- |
   | 作业层 | **PM** | 一开始 | 这件活要不要 architect（今天就有的大/小作业分道） |
   | 任务层 | **architect 提，用户在第 5 步盖章** | 任务表写出来时 | 哪些任务走双人，每个配一份钉死接口的 ADR |

3. **接口由 architect 钉，写成一份 ADR**，A 和 B 各读自己那一半。ADR 至少钉死那五件事：
   import 路径、导出名、签名、返回形状、出错行为。
4. **只有 architect 能改这份 ADR。** engineer 觉得钉错了，报给 PM；PM 起一个新的 architect 去改，
   并重跑已经按旧版本开工的那一半。这是把边界契约那条现成规则原样搬过来。

## 为什么这个形状对——三个理由都不是新发明的

1. **仓库的规则本来就要求它。** `principles.md:589`：每一个「怎么做」的决定都拿一个 ADR，
   **不论 job 多大**；判据是「有人要求过吗」。钉一个函数签名正是「怎么做」，没人要求过，是 crew
   干活时撞上的——**它本来就该有一个 ADR**。本 CRD 没有加流程，是在用一条已经在那儿的规则。
2. **它自带那道守卫。** PM 曾想把接口放进 `docs/design/api/`，唯一的理由是那里有「只有 architect
   能改契约」这条规则，能挡住「A 觉得名字不好就自己改掉」。走 ADR 一样有这条规则，而且不用把
   `docs/design/api/`（本来是「每一对会互相说话的模块一份」）塞进按任务分的文件。
3. **贵的形状只落在设计工作本来就值得做的地方。** 需要 architect 的活，才配得上双人的成本。

## 被否掉的两个位置（都是 PM 提的）

| 放哪 | 为什么否掉 |
| --- | --- |
| **写进 `docs/design/tasks.md` 那一行的 DoD 一节** | DoD 一节从此要装设计细节，而它原本只讲「done 是什么意思」。而且它没有「只有 architect 能改」这道守卫——engineer 自己就能改任务行里的字。 |
| **每个双人任务一份 `docs/design/api/` 契约文件** | 那个文件夹的定义是「每一对会互相说话的**模块**一份」。A 和 B 不是两个模块，是同一个任务的两半。塞进去会把那个文件夹的含义搞混。 |

## 它还带来一个好处:信号变锋利

名字和签名被钉死之后，A 和 B 还能分歧的东西只剩**行为**——具体的值、边界、错误路径。那正是
`CRD 0012` 想要的那一类歧义。钉接口不是削弱信号，是把噪音剥掉。

## 代价

- **每个双人任务的接口设计被提前到规划阶段。** architect 得先想清楚，不能留给 engineer 边写边定。
  这是真实的成本，只是它花在一个更便宜的时刻。
- **多出 ADR。** 一个作业里有几个双人任务，就有几份 ADR。按 `principles.md:589`，这本来就该有。
- **小作业那条路彻底没有双人形状。** 这是一条真实的边界。PM 判它是简化不是损失——小作业里的任务
  是改错字、一行修复，本来也不该上双人——但它必须写进文档，不能让读者自己去猜。
- **新的风险：ADR 自己变成第三份可能被误读的文档。** 两个 agent 读同一份 ADR，仍然可能犯同一个
  误读（`CRD 0012` 那节相关性失败的证据照样适用）。但一个签名比一段 DoD 散文难误读得多，净收益
  是正的。

| `CLAUDE.md` / 两份 README | 用户看得见 |
